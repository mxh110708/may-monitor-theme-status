# May Status 安装、外观与维护

基线：May Status 2.2.2-may.17 + May Monitor 0.1.0 + Deploy 0.9.38。先核对真实安装版本；源码主分支、构建 ZIP 和生产已应用的锁修订是不同状态。

## 安装前

确认 May Server 已完成初始化，节点由真实 Agent 持续上报，探测任务目标与协议正确。准备同组件一致性恢复点和当前主题锁。普通访问者不需要 Bun 或源码；维护者从发行版获取固定 ZIP，核对 SHA-256 和清单版本。

主题读取实际数据，不创建节点、不配置探测、不替代登录。首次私人站点公开前应单独检查节点和敏感字段的可见范围，不能用隐藏后台链接代替服务器鉴权。

## 暂存和应用

暂存脚本在**本主题仓库**，需连同 `stage-reviewed-theme.py` 使用，不在 Server 的 scripts 目录。将已审查的同一提交和发行 ZIP 放到自己的受控维护位置，从主题源码根目录执行：

```bash
sudo bash scripts/install-may-theme-update.sh '<THEME_PACKAGE.zip>' '<PACKAGE_SHA256>'
```

脚本需要 Python 3，先检查完整归档，拒绝路径穿越、重复项、符号链接、非静态成员及超限包。成功后在 `/usr/local/share/may-monitor/themes/<lock-sha256>/` 生成不可覆盖修订，输出主题锁摘要。这里只暂存，不自动停止／重启服务，不修改数据库和 DNS。

在 Deploy 选定已经核对 SSH、HTTPS、安装 UUID 的 Server，进入「应用已审查的静态主题」，填入锁摘要并审阅。应用先核对各文件、root 归属和写权限，再做一致性快照、切换并重启选定 Server。不要直接修改数据库或内嵌后台压缩 JS 来达到相同效果。

启用后分别验证公开首页、节点详情、实际历史、鉴权失败、无样本、报告过期和管理入口。静态 JS／CSS 检查内容和 MIME；缺失文件返回 404，HTML 200 不能算加载成功。

## 外观配置

后台「May Status 外观」只修改当前锁修订的 managed 配置。`short=GlassmorphismEnhanced` 保持原技术身份以读取已保存设置；不需要扫描旧目录、复制别名或开启任意扩展。

| 设置             | 当前行为                                                              |
| ---------------- | --------------------------------------------------------------------- |
| 默认主题模式     | 自动、浅色、深色；自动按北京时间 07:00–18:59 为浅色，其他时间为深色。 |
| 数据更新间隔     | 默认 3 秒，允许 1–60 秒；不是修改 Agent 的采样周期。                  |
| RPC 连接模式     | 默认 HTTP；选 WS 前核对反向代理升级支持。                             |
| 卡片／列表与尺寸 | 控制首页布局，不改变节点权限或数据。                                  |
| 总览和快捷控制   | 使用预设组合或按顺序填写自定义指标、筛选项。                          |
| 节点顺序         | 名称关键词规则与服务端顺序结合；名称不代替节点 UUID。                 |
| 地球／地图       | 立体、点阵、平面，支持停止旋转或隐藏。                                |
| 动画与背景       | 可减弱过渡；图片／视频由显式设置决定，视频可能增加浏览器资源。        |
| 价格／后台入口   | 仅改变展示；实际数据权限由 Server 决定。                              |

页面隐藏会停止实时读取并关闭相应连接，重新可见再取当前状态；这不停止 Server／Agent 的采集和告警。页面展示节流与服务器历史采样是两件事。

## 图标和背景

默认图标来自原始梅花照片的直接裁剪与缩放，保留原色，不是重新生成的花朵。详见[图标资源说明](DEFAULT-SITE-ICON.md)。在站点设置上传自有图标，或恢复默认；主题可另外配置 HTTPS／站内图标地址。优先级为明确外部图标 → 上传站点图标 → 默认图标。

外部图标、背景、访客信息及汇率功能可能发起相应网络请求；选择资源时核对可达性、隐私和内容许可。配置背景不应该改变指标或强制刷新全部用户浏览器缓存。

## 网络与历史

网络显示规则见[数据口径](NETWORK-DATA.zh-CN.md)。延迟原值不修正，失败率来自 `ping.loss`，缺少能力就显示不可用。公开页颜色、监控告警和 Route 故障切换各自独立。

机房／目标位置可通过 JSON 规则补充，需准确的城市参考坐标。冲突或未知时保持中性，不能使用访客 IP、国家中心或历史延迟猜测。七天选项受服务端实际保留和粒度约束。

## 更新与恢复

新代码必须使用新发行版本和新锁，不能原地替换已锁静态目录。先记录当前锁和设置，暂存新资源，再经 Deploy 同组件切换。升级 Server 保留已选择主题，但仍需验证接口合同和新静态资源。

「恢复内置界面」移除受管主题选择并重启 Server，不删除节点、历史、只读授权、外观设置和旧修订资源。恢复点仍引用的锁目录不能清除；恢复时必须存在同一组已核验资源。

主题包内两个 PWA 覆盖资源让 Worker 不拦截网络，防止旧导航兜底把管理页导向公开页。既有 Worker 的更新有浏览器时序，不自动强制清缓存或注销所有站点 Worker。更新问题先核对版本、请求、MIME 和锁。

## 故障定位

| 症状                 | 核对                                                                 |
| -------------------- | -------------------------------------------------------------------- |
| 所有节点未知         | Server 可达、鉴权、RPC2 结构与报告时间；保留最后有效值不代表仍在线。 |
| 丢包图不可用         | 配套版本、`ping.loss` 能力、任务与真实样本；不要估算补造。           |
| 延迟没有颜色评级     | 机房／目标坐标缺失、规则冲突或未知位置；真实延迟仍可显示。           |
| CPU 与负载看似不一致 | 使用不同轴；load 参考逻辑核心，不是百分比。                          |
| 管理页面错入公开页   | 内置路由、PWA 覆盖资源与实际 Worker 版本，不能只看首页。             |
| 主题启用被拒绝       | 文件摘要、root 所有权、写权限、锁身份和原事务，不关闭校验。          |

提交问题时写明 Server／主题版本、发生时间、浏览器、设置范围和脱敏请求结果，不上传 Token、数据库或完整备份。

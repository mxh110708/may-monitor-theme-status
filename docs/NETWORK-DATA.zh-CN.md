# 网络图表的数据口径

适用：May Status 2.2.2-may.17 与 May Monitor 0.1.0。主题只显示数据，不修改探测任务、代理出口、系统代理、学校网络或 Route 的切换策略。

## 延迟与评级

延迟显示服务端实际结果，不除以二、不按服务器历史归一化。ICMP、TCP 和 HTTP 的测量阶段不同，不能把任意探测称为用户完整代理请求耗时。

地理模式根据机房与检测目标的城市参考点计算大圆距离，以 `距离 / 100` 得到光纤往返传播下界的毫秒参考。四级上界分别由该参考乘 1.3／1.5／1.85／2.3，加 15／20／20／25 毫秒后向上取整到 5 毫秒；相邻等级至少间隔 10 毫秒。该统一公式不输入线路运营商、ASN、历史延迟或浏览器位置。

广州参考点与洛杉矶的当前示例上界为 170／195／240／295 ms。它们是主题显示策略，不是实际海缆长度或行业标准；不能拿来替代 Route 的 HTTPS 分地区上限。

固定模式的四级上界为 60／100／160／200 ms。未知或有冲突的位置不评级，真实数字仍展示。内置识别仅覆盖代码中明确的城市／目标标签；SF、SJ 等新名称不能假定都已自动识别，可用准确坐标补充。

## 地点补充

后台分别提供机房和探测目标规则，格式为 JSON 数组，按名称关键词匹配。以下只是城市级说明示例，不是真实节点：

```json
[
  {
    "match": "Example-LA",
    "label": "洛杉矶参考点",
    "latitude": 34.05,
    "longitude": -118.25
  }
]
```

补充规则优先，多项冲突时保持未知；不使用国家中心或访客 IP 在线位置兜底。广东任务使用广州作地区参考点，具体目标不在该地区时应调整，而不是为了改善颜色更改坐标。

## 失败比例

丢包视图读取 `ping.loss` 比例及每桶探测次数，按次数加权；不对一个降采样延迟值推断整桶成功率。100% 失败是合法值，缺测为空，不插值成零。缺少指标、不兼容、鉴权或网络错误分别交给状态处理，**没有估算回退**。

失败比例反映对应探测，不保证实际应用、TCP 重传或 UDP 包具有同一比例。运营商、IPv4／IPv6、任务目标和时间窗口不同的数据不混算。

## 历史、负载和证据

页面时间选项受 Server 的分钟／五分钟／小时保留层级限制。较粗历史按实际粒度展示，不能宣称拥有已清理的高频原始记录。

CPU 使用率在左轴 0–100%，系统负载在右轴并参考逻辑核心。报告过期、Server 不可读取和离线不是零资源。排错保留时间、版本、任务、粒度和状态，先确认数据再评判颜色。
